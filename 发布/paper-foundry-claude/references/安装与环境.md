# 安装与环境

## 1 安装（两端共用一份源）
```bash
cd /Users/bytedance/数模自动化
bash .claude/skills/paper-foundry/scripts/安装.sh          # 链接到 ~/.claude/skills 与 ~/.codex/skills（$CODEX_HOME 优先）
bash .claude/skills/paper-foundry/scripts/安装.sh --检查   # 只核对链接与 codex CLI
bash .claude/skills/paper-foundry/scripts/安装.sh --卸载
```
- 发布版：`bash 发布/paper-foundry-claude/scripts/安装.sh`（只装 `~/.claude/skills/paper-foundry-claude`，默认引擎 claude）、`bash 发布/paper-foundry-codex/scripts/安装.sh`（只装 `~/.codex/skills/paper-foundry-codex`，默认引擎 codex）。两份都由 `scripts/打包.sh` 从核心生成，不要手改发布版。
- Claude Code：在仓库内打开即自动发现项目级 skill（`/paper-foundry`）；仓库外靠用户级链接。
- Codex：`$paper-foundry` 或自动匹配；UI 元数据 `agents/openai.yaml`。
- 链接而不是复制：`git pull` 之后两端立刻是新版。skill 目录里没有任何密钥、端点、模型名以外的敏感信息，可以随仓库提交。
- 从仓库外调用脚本时，`公共.sh` 用 `pwd -P` 回到物理路径向上找含 `流水线/蜂群驾驶.py` 的目录；找不到就 `export SHUMO_PROJ=/Users/bytedance/数模自动化`。

## 2 体检（开炉前 / 换机器 / 体检不过时）
```bash
bash .claude/skills/paper-foundry/scripts/体检.sh [产出目录]
```
逐项打印 ✓/✗/?：项目根、`codex` CLI 与版本、`~/.codex/config.toml` 是否存在（**只看存在，不读内容**）、`xelatex`/`gs`/`pdftoppm`、venv 与科学栈（numpy/pandas/matplotlib/scipy/sklearn）、Fandol/Noto 字体、磁盘剩余（<20 GB 警告）、skill 链接、同父目录是否有驱动在跑、切换锁是否残留、git 是否干净。✗ 为硬失败（不要开炉），? 为提醒。

## 3 环境要件与用途（`流水线/运行时/环境就绪.sh` 幂等补装）
| 要件 | 用途 | 缺了会怎样 |
|---|---|---|
| `codex` CLI（fnm node 别名目录 `~/.local/share/fnm/aliases/default/bin`） | 每条角色腿 | 腿起不来：`腿死亡` 反复 |
| `~/.codex/config.toml`（端点、模型、reasoning） | 腿的端点/模型 | 腿立即失败；**本 skill 不读不改它** |
| `claude` CLI（Claude Code ≥ 2.1，`~/.local/bin/claude`）+ 登录态或 `~/.claude/settings.json` | `--引擎=claude` 时的每条腿 | 腿在 ~3 分钟后 401 或立刻 `Not logged in`；**本 skill 不读不改**，用 `体检.sh --引擎=claude --探针` 看 CLI 原话 |
| texlive（xelatex）+ Fandol 字体（文件名加载） | 编译论文 | `编译# E>0`/挂死（R39） |
| ghostscript、poppler（pdftoppm） | 页图渲染给评委模拟/美化师/终审 | `美化：无渲染页，跳过`、评委弃权 |
| graphviz、coreutils | 思路图、`timeout` 等 GNU 工具（脚本里仍不依赖 GNU timeout） | 局部失败 |
| `流水线/运行时/venv`（numpy/pandas/matplotlib/scipy/sklearn/statsmodels/sympy/networkx/pypdf/openpyxl/python-docx/lxml） | 求解/复算/绘图脚本；驱动把它放 PATH 首位 | `No module named numpy`（P8 提醒腿只用裸 `python3`） |
| Noto Sans CJK SC（绘图兜底字体） | 图内中文 | 方块字 |
| 磁盘 ≥20 GB | 镜像 1.5 GB + 日志 1 GB/炉 | 编译/腿写盘失败，表现诡异 |

## 4 网络与沙箱
- 腿通过 seatbelt `workspace-write` 跑：写权限锁在工作根；`/tmp` 被排除（`exclude_slash_tmp=true`）；只放行 `~/Library/texlive` 缓存。腿写工作根外一律失败——这是设计。
- 腿需要联网到 `config.toml` 里的端点；Codex 端起驱动/切换/停跑的命令要在**沙箱外**执行（否则无网、不能 kill 进程组）。
- 无外网给腿：不 `pip install`，不下载（AGENTS.md 已写）。
- `--引擎=claude` 的腿没有 seatbelt：靠 `--permission-mode acceptEdits`（编辑只自动放行工作根内）+ 工具白名单 + 禁 WebFetch/WebSearch；写出工作根不是硬锁，靠 AGENTS.md 与角色文件约束。要硬锁请用 codex 引擎。

## 5 升级与回滚
- 升级：`git pull`；改了驱动/运行时要 `bash scripts/验证.sh --干跑=全链,…`；正在跑的炉不受影响（驱动只在启动时加载）。
- 回滚：`git checkout <提交> -- 流水线 .claude/skills/paper-foundry`，再验证。驱动历史备份 `流水线/蜂群驾驶_v*备份*.py` 只供对照，不要拿来跑。

## 6 目录体检口诀
输入目录只放题目 PDF + 附件；产出目录 `成品_<名>` 与 `状态.json`/`台账/`/`蜂巢镜像/`/`驾驶_<名>.out` 同父目录；一个父目录一炉；旧炉先归档再 `--全新`。

## 7 两种引擎的鉴权口径与本机实测（2026-09-10）
| 引擎 | 鉴权在哪 | 本 skill 做什么 | 本机实测 |
|---|---|---|---|
| codex | `~/.codex/config.toml` | 只看文件存在 | 对照跑 411 腿全程可用 |
| claude | `claude /login` 的登录态，或 `~/.claude/settings.json` 的 `env` 块（`ANTHROPIC_BASE_URL`/`ANTHROPIC_API_KEY`/`ANTHROPIC_MODEL` 等） | 只看文件存在；`--探针` 真调一次 `claude -p` 并转述原话 | 带用户 settings：CLI 指向已退役的自定义端点，`--model sonnet` 也被 env 的模型名覆盖，约 3 分钟重试后 `401 API key is invalid`；跳过用户 settings（`--setting-sources project`）：`Not logged in · Please run /login`。结论：**本机要跑 Claude 版得先由用户登录或改 settings.json，本 skill 不代劳** |
探针命令等价于：`claude -p "只回答两个字：可以" --output-format text --model sonnet --max-turns 1 --no-session-persistence </dev/null`（stdin 必须关，否则永远挂着）。
