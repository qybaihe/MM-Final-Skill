# 切换手册：链路修好了，等某个边界再上线

「切换」= 等驱动日志出现某个标记 → 干净停跑 → （钩子：改状态/台账/稿件）→ 验证 → `--resume` → 核验新驱动。它把「改驱动代码必须重启」这件事变成零人工守候：你可以在白天修链路，让脚本在凌晨的轮次边界自动上线。

## 1 什么时候用
| 情形 | 标记（`--标记` 正则，在**当前段**日志里匹配） | 说明 |
|---|---|---|
| S2 某问过门后上线 | `门\[G2:问2\] 第\d+次检查 PASS` 或 `过门=` | 问级边界，下一问从新代码起 |
| S5 某轮修订落盘后上线 | `checkpoint\[S5-轮2修订后\]` | R43 轮级断点：续跑从下一轮起，不重跑本轮任何腿（10:26 实战） |
| G5 某次检查后上线 | `门\[G5\] 第2次检查 FAIL` | R49/R50/R52 三次实战都在这里切 |
| 立即切换 | 标记写一个已经出现过的行 | 脚本发现标记已在当前段就立刻切 |
不要在 wave 中途切：正在飞的腿会被 TERM，本波次重做。

## 2 命令
```bash
cd /Users/bytedance/数模自动化
bash .claude/skills/paper-foundry/scripts/切换.sh 真题测试/输入 真题测试/成品_对照版 \
  --标记 '门\[G5\] 第2次检查 FAIL' \
  --钩子 /path/钩子.py \
  --干跑=全链,G5图路,G5算条,G5页数 \
  --最长 7200
```
- 脚本第一件事是把自己和依赖复制到 `$TMPDIR/qiehuan.*` 再 `exec`（铁律 2：运行中的 bash 脚本原地改写会跑飞——10:29 双驱动事故的根因就是我改写了正在 `sleep` 的切换脚本）。复制之后源文件随便改。
- 锁：`<父目录>/.切换.lock`（pid）。`已有切换在等` 且 `kill -0` 不活 → 删锁。
- 退出码：0 完成；2 驱动先退出；3 等标记超时；4 没停净；5 钩子失败；6 验证失败；7 续跑启动失败；8 新驱动 60 s 内退出。非 0 时驱动都处于**已停**状态（除 2/3），人工处理后 `启动.sh --resume`。
- 后台挂：Claude Code 用 Bash `run_in_background`；Codex 在沙箱外用 `nohup bash … > 切换.log 2>&1 &`（脚本自复制，nohup 可用）。

## 3 钩子：停净之后、续跑之前改东西
钩子在项目根执行（`.py` 用 `python3`，`.sh` 用 `bash`），失败即不续跑。它是唯一可以安全改 `状态.json`/台账/镜像稿件的时刻（铁律 4）。

用 `scripts/钩子样板.py` 起手（有 `--演练`）：
```bash
python3 .claude/skills/paper-foundry/scripts/钩子样板.py --父目录 真题测试 --演练 \
  --恢复 论文/8.3.问题三源码.tex=真题测试/蜂巢镜像/日志/G5返工1_修订前/8.3.问题三源码.tex --留底 G5返工1_页数守卫 \
  --状态 美化后页数=68 \
  --并入 /path/条目.json --轮次 7 --来源 页数守卫
```
- `--恢复 镜像相对路径=来源文件`：先把当前版本留底到 `蜂巢镜像/审稿/回退稿/<留底标签>/`，再覆盖。
- `--状态 键=值`：`状态.json` 是**扁平字典**（`美化后页数`、`S5已完成轮`、`门失败计数`…），值按 JSON 解析（`68` 是整数，`"x"` 是字符串）。
- `--并入 文件.json`：条目数组，每条至少 `级别/目标/问题/定位/指令/验收/来源`；走 `回路.台账.并入()`，id 自动分配 `审-{轮次}-{序}`；级别 `硬伤|正确性|叙述|版式`，目标 `算|图|文`。
- `--演练` 只打印将做什么，不写。真跑前一定先演练。

R52 实战钩子做的三件事（16:37:50 成功）：① 8.3 从 `日志/G5返工1_修订前/` 恢复、新稿留底；② `状态.美化后页数=68`（旧炉续跑没有这个基线，页数守卫会静默）；③ 并入一条 正确性/文 条目（指令：不塞源码地重写 8.3 入口说明，路径+SHA256+linerange ≤80 行）→ 生成 `审-7-01`。

## 4 切换之后核验什么
新驱动 60 s 内应打出：`===== 后台启动`、`节点[…] 已完成，跳过（续跑）`×N、（S5 内）`S5 续跑：前 N 轮已落盘，从轮 N+1 继续`、`本地基座同步`、下一波次 `先启 [...]`。再看：
- `状态.sh` 的 `腿数` 在涨、活腿 ≤ 并发。
- 修的那条链路第一次触发时的日志行（例：R51 → `编译#G5返工1复核前0`；R52 → `!! 页数守卫[…]` 或不再触发）。
- 钩子改的东西：台账条目出现在下一次门检明细里；`状态.json` 键在。
把这些行摘进 `施工日志.md` 与 `病根台账.md` 的「真跑验证」列。
