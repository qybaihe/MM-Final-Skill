# 病根登记（每次插手或发现「换个地方还会再犯」的原因时）

## 病根台账.md 加一行（表格列与文件头一致）
`| R<n> | 病根（一句话：谁在什么条件下必然出错） | 证据（日志行/文件/时间，可回查） | 归属（链路 / 提示词 / 契约 / 环境） | 修法（改了哪个文件哪个函数） | 检测（以后怎么一眼看出它又犯了：日志里 grep 什么、哪个单测/干跑场景） | 状态（已修·真跑验证 / 已修·待验证 / 未修） |`

要求：
- 先修链路再改提示词；提示词改动必须写明「链路已排除」。
- 检测机制是硬要求：没有检测的修复默认「待验证」。
- 未闭环的不许删；闭环时把状态改成「已修·真跑验证」并写验证证据（哪炉哪一行）。

## 提示词层病根（P 系列）另立一节，同样七列
`| P<n> | 病根（哪个角色在什么提示下必然做错） | 证据（回流次数/耗时/台账条目，可回查） | 归属（角色/xx.md 条款名 + 驱动任务文本位置） | 修法（追加了什么条款/可选字段） | 检测（跑后指标哪一项、哪个文件该出现） | 状态（已落地待冒烟 / 已落地·冒烟过 / 已落地·真跑验证） |`

要求（铁律 15）：先证明链路没错（驱动派对了、收对了、判对了）再动提示词；条款正文里写一句证据；只追加不删；schema 只加可选字段；`契约核对.py` 过；改动最大的角色 `角色冒烟.py <角色> --根=<副本根>`；下次 --resume 生效后用回流账验证并改状态。

## 施工日志.md 加一条（在当前 M 章节末尾）
`- HH:MM <做了什么>（R<n>）：证据 → 根因 → 修法 → 验收（py_compile / 单测 n/n / 干跑场景 / 真跑日志行）`

## 提交
```bash
git add 流水线 病根台账.md 施工日志.md .claude/skills/paper-foundry
git commit -m "R<n> <一句话>"
```
不提交运行产物（`真题测试/状态.json`、`运行日志.md`、`*.out`、`蜂巢镜像/`）。
