# 监督清单：日志线索 → 含义 → 处置

节奏：开炉后 5 分钟看一次（S0 基建/读题过没过）；之后每 20–30 分钟 `状态.sh`；插手窗口是 **S2 每问过门后**、**S5 每轮 `checkpoint[S5-轮N修订后]`**、**G5 前**；G5/S6 时段每 10 分钟。`看守.sh` / Monitor 的事件正则在 `scripts/公共.sh` 的 `WATCH_RE`。

| 日志线索 | 含义 | 处置 |
|---|---|---|
| `门[Gx] 第n次检查 PASS/FAIL` | 门检；FAIL → 返工（≤2）→ 升格 → 降级放行 | FAIL 明细是流程性的（编译失败、缺文件、审计崩）→ **要插手**：停跑修链路。科学性 FAIL 让链路自己走 |
| `!!!! 门[...] → 降级放行` | 额度烧完放行，进 `状态.json` 降级放行 | 不插手；进交付报告「需人工关注」。已降级的问 S5 回炉后 G2 只复检一次（R44） |
| `红队不齐（n 处超容差）→ 派仲裁腿` | 独立复算与建模师超 1% | 正常。同一问 ≥3 次看分歧是不是口径/单位差（容差 `红队容差`） |
| `升格蜂群[...]` / `升格裁决` | 两次未消解换法重做：3 变体 + 裁决 + 解读 | 正常但贵（1–3 h/次）。同一问多次升格 = 门判据或提示词问题 → 记病根 |
| `429` | 端点限流；下一波次并发自动 −1（下限 2） | 连续出现 → **要插手**：停跑，`--并发=3` 续 |
| `rc=142` | 腿超上限被 with_timeout 杀，done 只剩 AUTO | 偶发正常（驱动重派一次）。同名腿连续两次 → 任务太重：拆批或提该波次 timeout（病根） |
| `孤儿` / `状态.sh` 的 codex 数 > 并发上限 + 1 | 腿进程组没被回收 | **要插手**：`停跑.sh` 会按 pid 文件回收；记 R32 类病根 |
| `Traceback` / `!! 驾驶异常终止` | 驱动崩 | **要插手**：看栈 → 修 → `验证.sh` → `--resume` |
| `腿死亡` / `重派` | kill -0 判死，整组回收当轮重派 | 偶发正常。同名腿反复死 → 看 `蜂巢镜像/日志/<腿>.log` 尾部（多为 codex 起不来/沙箱拒写） |
| `!! 预算护栏` | MAX_HOURS/MAX_LEGS 到顶，转应急出版 | 想继续：停跑后改 `配置["MAX_HOURS"]`（续跑按累计机时算，不算停跑间隔）再 `--resume` |
| `变化守卫[...] 超线 → 回退` | 定向修改被改成重写，整份回退（留底 `审稿/回退稿/`） | 偶发正常。某章反复回退 → 病根（守卫尺 or 修改腿越界）；源码章免检（R47） |
| `结构守卫` | `\input` 集/空章变化，整轮回退 | 同上 |
| `编译#... E>0` | xelatex 错误 | 驱动走编译修复循环（编修腿）。连续 3 次 E 不归零 → **要插手**：看 `蜂巢镜像/论文/论文.log` |
| `熔断升格` / `熔断搁置` | 台账条目两次未消解：硬伤/正确性升格一次再搁置，叙述/版式直接搁置 | 正常；搁置的阻塞级在 G5 再给一次机会 |
| `S5 轮n 面板均分` 连续下降 / `相对判断=更差` | 修订改坏了 | 驱动会按快照回退；连续两轮更差 → **要插手**：看 `审稿/回执_*.json` 谁越界 |
| `S5 轮数上限：仍有 n 条阻塞级` | 审稿场到轮数上限退出 | 不插手；G5 返工先走图路（R49）再改文；复盘会看见；写进报告 |
| `编译# P=` 页数骤变 | 增 >1 页：美化撑页（有页数守卫回退）；减 >20%：删重复/删章 | 减得多时 diff 章文件大小与 `\input` 数，确认不是丢章（本炉 113→68 = 删附录重复源码，合理） |
| 活腿 0、驱动在跑、10 分钟无新日志 | 驱动在编译/审计/渲染页（xelatex + pdftoppm 慢） | 看 `xelatex数`；30 分钟无新日志 → **要插手**：`ps` 看驱动卡在什么子进程 |
| 驱动不在跑且无 `终态：` | 被杀/机器睡眠/崩 | **要插手**：看日志尾，`--resume` |
| `S5 续跑：前 N 轮已落盘` | R43 轮级断点接上 | 正常；本轮不做回退（上一轮快照不在内存） |
| `弃权票 n` | 评委模拟只看前 8 页，裁不了的写「未核实」不算否决（R45） | 正常 |
| `代码章不设守卫` | 源码章随求解器换版整份替换（R47） | 正常 |
| `先启 ['G5返工图N']` / `脚本 求解/成图回炉G5_N.sh` | G5 返工图路（R49）：绘图师改脚本、只重跑受影响图，再派撰稿师、猎手复核 | 正常；成图 rc≠0 走修复腿一次；仍不过则第 3 次检查降级放行，把图条写进报告 |
| `G5 返工N：n 条 目标=算 的阻塞级无路可派 → 搁置` | G5 没有算路（R50）：算条记搁置理由，不派撰稿师空转 | 正常；这条会让 G5 降级放行，进报告「需人工关注」 |
| `编译#G5返工N复核前: E=… P=…` | G5 返工改完、猎手复核前的编译（R51） | 缺这行 = 猎手在判旧 PDF，图/文改动会被误判未消解 |
| `!! 页数守卫[G5返工N]：P 页 > 美化后基线 B+t → 回退本轮代码章 […] → P2 页` | 撰稿师把整份源码塞进附录（R52） | 看 `审稿/回退稿/G5返工N/`；回执被作废的条目会以 未消解 重派；若 `状态.美化后页数` 缺失（旧炉续跑），守卫静默不动——用钩子补 |
| `脚本 求解/xxx.sh 第1次 rc≠0` → `先启 ['修脚本_xxx']` → `第2次 rc=…` | 求解/成图脚本首跑失败，驱动派一条修复腿再跑一次（`repairs=1`） | 第 2 次仍 rc≠0 驱动照常往下走（图可能没重出）：看 `蜂巢镜像/日志/<脚本名>.log` 末行。三类高发根因见 `故障手册.md` C 节（断言致死 / 腿用了 PATH 外的 python 没 numpy / 成图批脚本自设预算+字体缓存）。同一炉修复腿 >4 条 → P8 类病根 |
| `先启 ['美化图N']` / `脚本 求解/成图美化N.sh` | 美化师标 `目标=图` 的页问题直接派绘图师改脚本重出图（P6），文条照旧派 `排版执行N` | 正常；两路共用一次编译与页数守卫。若仍见撰稿师回执大量 `转路`，说明美化师没标 目标 |
| `编译#G5返工N复核前0: E=0 … P=` | R51 真跑证据（对照跑 17:01:39：P=68） | 正常；缺这行 = 猎手会按旧 PDF 判 |
| `!! 结构守卫[G5返工N]：… 源码清单减少 2→1 → 回退` | 撰稿师把两个 lstlisting 合成一个，结构守卫按「附录源码清单数不减」整份回退（R38 尺子），新稿留底 `审稿/回退稿/G5返工N/` | 不插手（会按未消解重派或降级）；但记进报告：指令（如「≤80 行入口片段」）与守卫尺（清单数不减）打架时，腿必输——要么指令写明「保留清单数」，要么用户改尺子 |
| `交接/换版清单_问题X.json` 出现在回炉算之后 | P3：建模师回炉重算后写旧值→新值→出现处清单，撰稿师/绘图师按它同步，猎手查残留 | 正常。回炉算后**没有**这个文件 = 建模师没按协议 5 做：下一轮解读返工单会加一条；连续缺失 → 冒烟建模师 |
| 红队报告含 `口径对照`、结论 `对齐` 但 分歧明细 有 `类型=口径` | P1：两套口径生效，口径差异不再触发仲裁 | 正常。若一问仍出现 ≥2 次「仲裁裁定 口径差异成立」→ 解读师的口径说明没写四段，看 `交接/结果声明_问题X.json` |

## 每炉必看的三处产物
- `<父目录>/状态.json`：阶段、腿数、问题门状态、门失败计数、降级放行、S5已完成轮、累计机时。
- `<父目录>/台账/审稿台账.json`：待改/待复核/已消解/未消解/搁置；`升格过`、`尝试次数`。
- `蜂巢镜像/审稿/`：`审稿意见_轮N{A,B}.json`、`硬伤_轮N.json`、`评委模拟_轮N.json`、`裁定_*.json`、`回执_*.json`、`复盘报告.json`。
