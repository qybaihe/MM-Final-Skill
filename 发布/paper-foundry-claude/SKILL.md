# 论文铸造厂操盘手册

> **本版本：paper-foundry-claude**（由核心 `.claude/skills/paper-foundry` 经 `scripts/打包.sh` 生成，勿手改）
> - 默认腿引擎 **claude**（`scripts/引擎.default`）：每条角色腿是一个 `claude -p` 无头子代理——系统提示 = 工作根 AGENTS.md + 角色文件，任务作用户消息，`--effort` 吃同一张角色分档表，腿内可再开 Agent 子代理。
> - 宿主 Claude Code：`bash scripts/安装.sh` 只装到 `~/.claude/skills/paper-foundry-claude`，调用 `/paper-foundry-claude`。
> - 第一炉之前必做 `bash scripts/体检.sh <产出目录> --引擎=claude --探针`（真调一次 `claude -p`，只转述 CLI 原话；401/未登录是用户侧配置，本 skill 不读不改密钥与端点）。Claude 引擎尚无整炉实跑数据，先 `--档位=快速` 冒一炉。
> - 想用 codex 腿：`启动.sh … --引擎=codex`（引擎只在开炉/续跑边界换，铁律 20）。

给定赛题 PDF + 附件，`流水线/蜂群驾驶.py` 在本机跑完 S0 读题 → S1 锦标赛 → S2 建模/红队 → S3 图证 → S4 撰稿 → S5 审稿场/美化 → G5 出版门 → S6 终审出版复盘，产出可提交的论文（PDF + tex + 图 + 求解脚本 + 全套交接文件）。本 skill 管**怎么体检、怎么开炉、怎么盯、何时插手、怎么切换、怎么改提示词、怎么收尾交付**，不管论文本身怎么写——论文由 17 条角色腿写，你是操盘手不是作者。

所有脚本在 `scripts/`，只需要一个参数（产出目录）就能推出同炉的其它路径；符号链接装到仓库外也能用（找不到项目根时 `export SHUMO_PROJ=<仓库>`）。每条规则后面都有一次真事故，证据在 `references/铁律.md` 与 `references/经验沉淀.md`。

## 0 先分清三件事
| 你在做什么 | 用什么 | 不许做什么 |
|---|---|---|
| 操盘（开炉、盯、停、切、收尾） | `scripts/*` + `references/监督清单.md` | 不手工解题、不替腿写论文、不下载外部材料（除非用户明确许可） |
| 修链路（驱动/门检/回路/运行时脚本） | 停 → 改 → `验证.sh` → 干跑场景 → `--resume` | 不原地改写运行中的脚本；停净前不碰 状态/台账/镜像 |
| 改提示词与约束（角色文件、任务文本） | 证据 → P 编号 → 追加不删 → `契约核对` → 冒烟 → 下次续跑生效 | 不改门判据/阈值/守卫尺/蓝图（用户的决定）；不为「感觉」改提示词 |

**密钥纪律**：端点与 KEY 只在 `~/.codex/config.toml`。本 skill 不读、不改、不复制、不写进任何新文件/日志/报告；`体检.sh` 只看该文件是否存在。

## 1 每次接手先读（10 分钟）
1. `交接提示词.md`（架构与环境铁则）→ `施工日志.md` 末尾 10 条 → `病根台账.md` 末尾（R 编号与 P 编号排到哪）→ 本目录 `references/铁律.md`。
2. 看这炉：`bash scripts/状态.sh <产出目录>`；再看 `<父目录>/状态.json`、`台账/审稿台账.json`、`蜂巢镜像/审稿/`。
3. 目录约定：输入目录 = 题目 PDF + 附件；产出目录 `<父目录>/成品_<名>`；驱动把 `状态.json`、`台账/`、`蜂巢镜像/`（工作根）、`运行日志.md` 放在**同一父目录**，stdout 记到 `<父目录>/驾驶_<名>.out`（pid 同名 `.pid`，实际日志路径记在 `<父目录>/.驾驶_日志`）。**一个父目录只住一炉。**

### 2.1 开炉 / 续跑
腿引擎用 `--引擎=codex|claude` 指定（发布版各自有默认，见 §4）；续跑不传就沿用 `状态.json` 里记的那个，显式换引擎时驱动日志会打「!! 腿引擎切换」。引擎只在开炉/续跑边界换，炉中不换（铁律 20）。
- 档位：`深度`（默认，全开：路线 3、摘要变体 5、审稿 4 轮、全员 `CODEX_EFFORT`）/ `标准`（变体 3、审稿 3 轮、角色分档 xhigh/high/medium、MAX_HOURS 30）/ `快速`（冒烟：所有节点各走一遍）。阈值、门判据、守卫尺任何档位都相同。
- `--并发=4` 是实测稳定值（6 并发曾整晚 429；4 并发一炉 0×429）。`--effort=xhigh` 是对照口径。
- 脚本会拒绝：同父目录已有驱动（双驱动）；无 `--resume` 却已有 `状态.json`（重开加 `--全新`，S0 会清空镜像）。
- 角色文件、`AGENTS.md`、`bin/` 脚本只在启动/续跑时同步进工作根；驱动代码只在启动时加载。所以：改驱动 = 停 + 验证 + 续；改角色 = 下次续跑/新炉生效，跑炉中改是惰性的（铁律 5/15）。

### 2.2 监督节奏
开炉后 5 分钟看一次（S0 基建、读题过没过）；之后每 20–30 分钟一次 `状态.sh`；插手窗口是 **S2 每问过门后**、**S5 每轮 `checkpoint[S5-轮N修订后]`**、**`门[G5] 第N次检查`**；G5/S6 时段每 10 分钟。只在监督清单标「要插手」的情形插手，科学性 FAIL 让链路自己走（返工 → 升格 → 降级放行是设计好的出口）。

### 2.3 插手四步：停 → 改 → 验 → 续
1. 停：`停跑.sh` 退出码 0 才算停净；残留用 `ps -eo pid,pgid,etime,command | grep -E 'codex exec|蜂群驾驶|xelatex'` 看清再 `--强制`。
2. 改：流程/编排问题**先修链路**再想提示词。动了 `流水线/**/*.py` 或 `运行时/*.sh` 必须 `验证.sh`；改了编排（节点/门/续跑/回炉/G5）必须跑对应干跑场景（`全链,中断续跑,级联,门升格,韧性,S5续跑,G5图路,G5算条,G5页数`）。
3. 验：新干跑场景先让它失败一次再修（否则你不知道它验了什么）。
4. 续：`--resume`（节点级 + S5 轮级断点自动接上）。续跑后看一眼 `编译#` 与页数（铁律 14）。

### 2.4 收尾
见到 `终态：` / `驾驶结束`：`跑后指标.py --markdown` → 按 `references/交付报告模板.md` 写报告（质量指标对照、门史、可靠性、机时、**回流账**、链路修复、复盘观察、需人工关注、下一炉建议）→ 成品 `<产出>/论文/论文.pdf`、复盘 `审稿/复盘报告.json`、运行摘要 `<父目录>/运行报告.md` → 台账状态闭环（R/P 行「已修·真跑验证」要写证据行）→ 提交 → 更新记忆/交接文档。

## 3 铁律（一句话版；证据与做法见 `references/铁律.md`）
1 一个父目录只起一个驱动 · 2 运行中的 bash 脚本绝不原地改写 · 3 杀腿组前先验 pid 是不是腿 · 4 停净之前不动 状态/台账/镜像 · 5 驱动代码启动时加载，角色/AGENTS/bin 续跑时同步 · 6 改完必过 `验证.sh`，改编排必跑干跑场景 · 7 增量不重写，先修链路再改提示词 · 8 病根带证据/归属/修法/检测进台账，不闭环不删 · 9 新角色先冒烟 · 10 密钥纪律 · 11 不越权改蓝图/阈值/门判据/守卫尺 · 12 不手工解题、不替腿写论文、不擅自下载 · 13 shell 里永远先 `cd <项目根>` · 14 每次续跑前看 `编译#` 与页数 · **15 提示词改动纪律：证据 → P 编号 → 只追加 → 契约核对 → 冒烟 → 续跑生效** · **16 每炉算回流账，同类回流超预算即病根** · **17 任何守卫豁免都配一把体量尺** · **18 评审指令必须是最小改动，撰稿师有体量纪律** · **19 开炉前看磁盘（镜像 1.5 GB、日志 1 GB/炉）**。

## 4 两个版本、两种引擎
本 skill 有两个发布版（`发布/paper-foundry-claude`、`发布/paper-foundry-codex`，由 `scripts/打包.sh` 从本核心目录生成，内容只差默认引擎、宿主安装目标与这一节的口径）。**宿主**（谁当操盘手）与**引擎**（谁跑角色腿）是两件事，可以交叉：Claude Code 操盘 + codex 腿是 2026-09 对照跑的口径；Claude 版默认 Claude Code 操盘 + `claude -p` 子代理当腿。

### 4.1 宿主差异（操盘手在哪运行）
| | Claude Code | Codex |
|---|---|---|
| 调用 | `/paper-foundry`（发布版 `/paper-foundry-claude`）；仓库内自动可用，仓库外需 `安装.sh` | `$paper-foundry`（发布版 `$paper-foundry-codex`）；需 `安装.sh` 链到 `~/.codex/skills` |
| 盯日志 | Monitor 工具（正则 `WATCH_RE`），或 Bash 后台跑 `看守.sh` | 只有 `看守.sh` 分段（每段 ≤ 命令超时） |
| 等待 | Bash 工具里前台 `sleep` 会被拦：用 Monitor/后台任务，不要轮询 | `看守.sh --秒 N` 自带等待 |
| 沙箱 | Bash 直接跑 | `启动.sh`/`切换.sh`/`停跑.sh` 必须**沙箱外**执行（腿要联网到端点、要 kill 进程组）：审批时选「在沙箱外运行」，或为工作区开 `network_access` |
| 通知 | 终态/异常可 PushNotification | 无；看 `看守.sh` 输出 |
| shell | 脚本按 macOS bash 3.2 写（变量名 ASCII、`${var}` 紧跟中文、进程判定只用 `pgrep -f`） | 同 |

### 4.2 引擎差异（角色腿由谁跑；驱动、门、守卫、台账、契约完全不分引擎）
| | `--引擎=codex`（Codex 版默认） | `--引擎=claude`（Claude 版默认） |
|---|---|---|
| 一条腿 | `codex exec`，提示 = 角色文件 + `=== 本次任务 ===` + 任务 | `claude -p`，系统提示 = 工作根 `AGENTS.md` + 角色文件（留档 `日志/<腿>.system.md`），任务作用户消息；腿内可再开 Agent 子代理 |
| 文件边界 | seatbelt `workspace-write`：写权限锁死在工作根，`/tmp` 排除 | 无 seatbelt：`--permission-mode acceptEdits` + 工具白名单（Bash/Edit/Write/Read/Glob/Grep/Agent），WebFetch/WebSearch 禁用；写出工作根靠提示词约束，不是硬锁 |
| 附图（评委/图评/美化/终审/复盘） | `-i 图.png`（≤8 张） | 图路径列进任务，腿用 Read 工具逐张打开 |
| 推理档 | `-c model_reasoning_effort=`，角色分档 `LEG_EFFORT` > 全局 | `--effort`，同名 low/medium/high/xhigh，同一套分档表；模型 `LEG_MODEL`（默认 `opus`） |
| 鉴权/端点 | `~/.codex/config.toml`（本 skill 不读不改） | 用户的 Claude Code 登录态或 `~/.claude/settings.json` env 块（本 skill 不读不改）；`体检.sh --引擎=claude --探针` 只转述 CLI 原话 |
| 进程判定 | `codex exec` | `claude -p`（`公共.sh` 的 `是腿`/`腿数` 两种都认） |
| 已知坑 | 429 → 并发闸自动降 1；孤儿进程靠 setsid 组回收 | stdin 必须关（否则永远挂）；嵌套在 Claude Code 里跑要清 `CLAUDECODE`；退役端点 → 约 3 分钟重试后 401；未登录 → `Not logged in · Please run /login` |
| 验证 | `流水线/验证/腿引擎分发.sh`（桩） + 干跑 `引擎` 场景 | 同；真腿冒烟 `角色冒烟.py <角色> --根=<副本>` 前先 `LEG_ENGINE=claude` |
| 实跑记录 | 2026-09 对照跑 411 腿、26.7 h（本文所有量级数字） | **尚无整炉实跑**：2026-09-10 本机 `claude -p` 因用户 CLI 指向退役端点（401）/未登录而不可用，只过了桩单测与干跑；换机或修好登录后先 `--档位=快速` 冒一炉 |

## 5 安装
`bash .claude/skills/paper-foundry/scripts/安装.sh`：把本目录符号链接到 `~/.claude/skills/paper-foundry` 与 `~/.codex/skills/paper-foundry`（一份源，随 git 更新；`--宿主=claude|codex|both` 选端；`--检查` 只核对；`--卸载` 移除）。发布版同样：`bash 发布/paper-foundry-claude/scripts/安装.sh`（默认只装 Claude 端、默认引擎 claude）、`bash 发布/paper-foundry-codex/scripts/安装.sh`（只装 Codex 端、默认引擎 codex）；改了核心后 `bash scripts/打包.sh` 重新生成两份，`验证.sh` 会核对发布版与核心是否一致。Codex 端 UI 元数据在 `agents/openai.yaml`。环境补装 `bash 流水线/运行时/环境就绪.sh`（幂等）。细节见 `references/安装与环境.md`。
