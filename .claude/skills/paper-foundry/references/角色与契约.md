# 角色与契约：17 条腿各读什么、写什么、schema 权威在哪

角色提示词在 `流水线/角色/*.md`（`_备份_*` 是历史版本，不同步进工作根）。腿 = `bin/role.sh <角色文件> <任务文件> <腿名>`：提示 = 角色文件全文 + `=== 本次任务 ===` + 驱动生成的任务文本；产物写在工作根；完成写 `日志/<腿名>.done`（≤5 行摘要）；页图类腿用 `bin/图片腿.sh`。推理档由 `LEG_EFFORT`（角色分档）> `CODEX_EFFORT`（全局）决定。

## 2 契约与所有权（`流水线/运行时/契约表.py` + `流水线/验证/契约核对.py`）
- 契约表只登记「这个产物的 schema 权威定义在哪」：`围栏`（角色 md 里紧跟路径的 ```json 块）/ `代码`（脚本写入语句）/ `无`（待办，核对会报错）。**刻意不复制 schema**——复制就制造第二个事实来源（R6/R13 的病）。
- 契约核对：消费方（门检/驱动/审计）读的每个字段，生产方都必须声明过；读侧容错（如 `消解`→`消解状态`）单列不进 schema。任何一次改提示词/改门检之后必跑；`验证.sh` 已包含。
- 登记在表的产物：题面契约、数据档案（无声明，待办）、计划（待办）、假设台账、结果声明、仲裁、红队报告（+驱动代写）、需求追踪矩阵、实验记录、审计报告、硬伤、评委模拟、复盘报告、审稿台账视图。`求解/问题N/结果/*.json` 是键池不是字段契约。
- 驱动持有的真相：`台账/{审稿,章评,美化}台账.json`（腿只看只读视图 `审稿/审稿台账_视图.json`）、`交接/返工台账_问题X.json`、`状态.json`。腿写这些 = 越权，G5 任务里明写封死。

## 3 腿与驱动之间的约定（腿必须遵守，否则驱动会重派/回退）
- 只在工作根内写；交接 JSON 合法（无注释无尾逗号）；完成写 done 标记（否则 `AUTO(rc=…)`）。
- 修改类腿：只改编号点名处，写回执（受理/改动/未改原因；「需转算/需转图」触发改路）；越界会被变化守卫（句子尺 45%、升格 70%）/结构守卫/页数守卫回退并作废回执。
- 评审类腿：意见带 `对应`（沿用上一轮 id）才会被合并而不是重开；带 `目标`（算/图/文）与 `级别` 才能分路分级；不带的由 `推断目标()` 关键词分路、默认级别兜底。
- 脚本类产出：只用 `python3`；自检不致命；成图不覆盖 `MPLCONFIGDIR`；每个脚本跑完打印结果摘要。

## 引擎与腿契约（两种引擎共用同一份角色文件与任务文本）
- **不变量**：腿在工作根里按角色 schema 写产物、完成写 `日志/<腿名>.done`；驱动只认 done 与产物，`收回执`/契约核对/守卫一律不看引擎。角色文件、任务文本、台账渲染、回执格式一字不改。
- **codex 腿**：`bin/role.sh` → `codex exec`（seatbelt workspace-write），提示 = 角色文件 + `=== 本次任务 ===` + 任务；AGENTS.md 由 codex 自动读。看图腿 `bin/图片腿.sh` 用 `-i`。
- **claude 腿**：同两个脚本按 `LEG_ENGINE=claude` 分发到 `bin/claude公共.sh`：系统提示 = `AGENTS.md` + 角色文件（留档 `日志/<腿名>.system.md`），用户消息 = `=== 本次任务 ===` + 任务；看图腿把图路径列进任务、腿用 Read 打开；`--effort` 直接吃分档表的 low/medium/high/xhigh；模型 `LEG_MODEL`（默认 opus）；`--no-session-persistence`；stdin 关闭。
- **冒烟**：`LEG_ENGINE=claude python3 流水线/验证/角色冒烟.py <角色> --根=<副本根>`（副本根同样别对活镜像）。桩级验证 `bash 流水线/验证/腿引擎分发.sh`（两种引擎的 flag/提示/附图/stdin/done 兜底 16 项）。
- **角色文件里的引擎相关措辞**：角色文件写的是「只用 python3」「不 pip install」「完成写 done」等与引擎无关的纪律；不要在角色文件里写 codex/claude 字样。
