# 故障手册：症状 → 根因 → 修法（全部来自真炉）

用法：先在左列找症状（日志行、脚本输出、进程状态），按「修法」做；标 **要插手** 的才停跑。每条后面括号里是出处（病根编号或施工日志时间）。

## A 启动类
| 症状 | 根因 | 修法 |
|---|---|---|
| `启动.sh` 报 `拒绝启动：父目录 … 已有驱动在跑` | 同父目录已有驱动（可能是上次没停净，或双驱动事故残留） | `停跑.sh <产出>`，确认 `驱动=0`，再启动。绝不 `--全新` 强开（铁律 1） |
| `!! 状态.json 已存在` | 上一炉断点还在 | 要续跑加 `--resume`；要重开加 `--全新`（S0 会清空 `蜂巢镜像/`——先把想留的成品拷走） |
| `找不到 codex CLI` | `codex` 不在 PATH（fnm 别名目录未进 shell PATH） | `本地蜂巢.py` 自己会找 `~/.local/share/fnm/aliases/default/bin`；启动脚本要在能 `command -v codex` 的 shell 里跑；Codex 端在沙箱外执行 |
| `?? 找不到 xelatex` / `?? venv 不存在` | 环境没备好 | `bash 流水线/运行时/环境就绪.sh`（幂等：texlive/ghostscript/graphviz/coreutils/poppler、Fandol/Noto 字体、venv 全栈） |
| 驱动 20 秒内退出 | 多为 Traceback（导入错、状态文件损坏）或输入目录无 PDF | 看 `启动.sh` 打印的日志尾；`python3 -m py_compile 流水线/蜂群驾驶.py`；状态文件损坏用最近的 `状态_*备份.json` |
| 编译/腿莫名失败，`df -h` 显示盘 >95% | 镜像 1.5 GB/炉、日志 1 GB/炉；本机曾剩 14 GB | `体检.sh` 会警告；归档旧炉、删旧炉 `蜂巢镜像/日志/*.log` 与 `论文/页/*.png`（铁律 19） |

## B 腿类（codex 角色腿）
| 症状 | 根因 | 修法 |
|---|---|---|
| `rc=142`，done 只剩 `AUTO(rc=142) 角色未写done标记` | 腿超过波次上限（`LEG_TIMEOUT`，多数 1100–1300 s，审稿/建模 1800–3600）被 with_timeout 整组杀 | 偶发正常，驱动重派一次。同名腿连续两次 → 任务太重：拆批或提该 wave 的 timeout（记病根） |
| `孤儿` / 状态.sh 里 codex 数 > 并发 + 1 | 旧版 with_timeout 只杀 node 包装，原生 codex 子进程逃逸（R31）；现版 setsid 整组回收，理论上不再有 | **要插手**：`停跑.sh` 按 pid 文件回收；仍有残留 `ps -eo pid,pgid,etime,command \| grep 'codex exec'` 看清 pgid 再 `kill -- -pgid` |
| `429` | 端点限流；驱动下一波次并发自动 −1（下限 2） | 连续出现 → **要插手**：停跑，`--并发=3` 续。4 并发实测一炉 0×429 |
| `腿死亡` / `重派` | `kill -0` 判死（进程没了但 done 没写） | 偶发正常。同名腿反复死 → 看 `蜂巢镜像/日志/<腿>.log` 尾：codex 起不来（端点/配置）、seatbelt 拒写（写到工作根外，包括 `/tmp`——`exclude_slash_tmp=true`） |
| `get_json … 带反馈重写` 后仍失败 | 腿产出不是合法 JSON / schema 不对（注释、尾逗号、顶层被字典包装） | 驱动会带反馈重派一次后放弃；反复出现 → 冒烟该角色，看 `角色/*.md` 的 ```json 围栏是不是被你改坏 |
| 腿 log 末尾 `hook: Stop` 后没有产物 | codex 会话结束但没写文件（多为路径写到工作根外或权限） | 看 log 里最后一次 `apply_patch`/写文件的路径；工作根外一律失败 |
| 活腿 0、驱动在跑、10–30 分钟无新日志 | 驱动在编译/审计/渲染页（xelatex 两遍 + pdftoppm 138 页很慢） | 看 `状态.sh` 的 `xelatex数`；30 分钟无新日志 → **要插手**：`ps` 看驱动卡在哪个子进程 |

## C 脚本类（求解 / 复算 / 成图脚本，驱动用 `run_script` 跑，失败派一条修复腿）
| 症状 | 根因 | 修法 |
|---|---|---|
| `ModuleNotFoundError: No module named 'numpy'` | 腿在脚本里用了绝对路径解释器或 `python3.x`（`/opt/homebrew/bin/python3` 是 3.14，没有科学栈）；驱动的 PATH 首位是 `运行时/venv/bin`，只有裸 `python3` 才落到 venv | P8 条款：只用 `python3`。已发生的：修复腿会改；反复 → 冒烟建模师/红队 |
| `AssertionError` 让整脚本 rc≠0 | 腿把自检写成致命断言（数据条件稍不满足即死） | P8：自检写 `结果/自检.json` 或结果 JSON 的 `诊断` 键，不 assert |
| 成图批脚本首跑 rc=1、修复后仍 rc=1（对照跑 16:46/16:48） | 脚本自设 750 s 总预算 + 单图 90 s，且判「旧图不能冒充本轮产物」按 mtime；新建的 `MPLCONFIGDIR` 让 matplotlib 重建字体缓存 30–60 s 吃掉单图预算 | P8 成图脚本纪律：不覆盖驱动的 `MPLCONFIGDIR`（工作根 `.cache/mpl`）、单图失败不整批非零退出、只看 PNG。已发生的：看 `日志/<脚本>.log` 与 `成图状态.json`，图没重出就等猎手复核把图条判未消解，下一轮再走图路 |
| 中文字体缺字（图上方块） | 绘图脚本没按 `AGENTS.md` 设 `font.sans-serif=['FandolHei','Noto Sans CJK SC','DejaVu Sans']`，或字体没装 | `环境就绪.sh` 装字体；脚本按 AGENTS 规范 |
| 读数据乱码 | `数据/data.csv` GBK、日期 `%d/%m/%Y`（本题） | `交接/数据档案.json` 是权威，腿必须读它 |
| 脚本跑了很久没 rc | `run_script` 有 budget（求解 900–1300 s、成图 800 s）；到点判死重派修复腿 | 正常；反复超时 → 建模师把重算拆成缓存 + 增量 |

## D 编译类（xelatex）
| 症状 | 根因 | 修法 |
|---|---|---|
| 续跑后第一次 `编译# E=97` | aux/toc 陈旧 | 驱动编译修复循环自愈（第二遍 E=0）；不插手 |
| xelatex 挂死不退出（曾 400 s 超时） | 模板按**字体家族名**加载（`\setmainfont{TeX Gyre Termes}` 类）在本机 CoreText 下查不到就挂（R39） | `format.cls` 已全改**文件名**加载；改版式的腿不许写家族名（AGENTS 已写）。挂住时 `pkill -x xelatex` 后驱动会走修复循环 |
| `编译# E>0` 连续 3 次不归零 | 腿写坏了 tex（未闭合环境、非法字符） | **要插手**：看 `蜂巢镜像/论文/论文.log` 第一处 `!`；回退该章到 `审稿/回退稿/` 或 `日志/*_修订前/` 的版本 |
| 页数骤增（68→112） | 撰稿师整份 `\lstinputlisting` 源码（R52） | 页数守卫回退代码章并留底；若基线缺失（旧炉续跑）守卫静默——用切换钩子补 `状态.美化后页数` |
| 页数骤减 >20% | 删附录重复源码（合理，113→68）或丢章 | diff 章文件大小与主控 `\input` 数；结构守卫会拦空章 |
| 摘要页 ≠1 | 摘要撑页 | 美化/摘要定稿会处理；G5 门检也看 |

## E 门 / 台账类
| 症状 | 根因 | 修法 |
|---|---|---|
| `门[Gx] FAIL` 明细是流程性的（缺文件、编译失败、审计崩、假阳性） | 链路问题 | **要插手**：停跑修链路。案例：R48 附录代码量不认外链 `\lstinputlisting` |
| `门[Gx] FAIL` 明细是科学性的（解读 FAIL、红队不齐、协议项） | 设计内 | 让链路走：返工 ≤2 → 升格 → 降级放行；进报告「需人工关注」 |
| G5 一直 FAIL，明细只剩 `目标=算` 的阻塞级 | G5 无算路（R50 直接搁置） | 不插手；这条必然导致 G5 降级放行；报告里写清算条内容与复盘意见 |
| `熔断搁置` 的图条明明已重绘 | 猎手按旧 PDF 判（R51 已修：复核前编译）；或猎手没写依据版本（P9） | 看 `编译#G5返工N复核前` 是否出现；看裁定文件的版本说明 |
| 变化守卫反复回退同一章 | 修改腿越界（整章重写）或点名粒度识别不到（R36 补②） | 看 `审稿/回执_*.json` 的 改动 字段与守卫日志的比例/点名数；越界 → 冒烟撰稿师；识别 → 链路 |
| 结构守卫回退「源码清单减少」 | 撰稿师把两个 lstlisting 合成一个（对照跑 17:01） | 指令与守卫尺打架：指令写明「保留清单数」，或用户改尺子；不擅自改尺 |
| 台账里同一意见换措辞反复出现 | 评审没带「对应」、`并入` 没合并 | 看 `台.并入` 的 合并/重开 计数；评审腿任务里有上一轮台账渲染，反复 → 评审角色冒烟 |
| 门检读的文件被腿改了（自造 `硬伤_轮5.json`） | L0 逃生路径 | 硬伤判据只认 `审稿台账_视图.json`（驱动上传）；G5 任务封死清单已写 |

## F 停跑 / 切换类
| 症状 | 根因 | 修法 |
|---|---|---|
| `停跑.sh` 说 `pid 不是驱动（pid 被复用）` / `跳过 …：pid 已被复用` | pid 文件过期 | 正常保护；用 `所有驱动`（pgrep）找真驱动 |
| `!! 未停净（残留 n）` | 腿还在 TERM→退出的窗口，或 xelatex 在跑 | 等 30 s 再跑一次；仍残留看 `ps -eo pid,pgid,etime,command`，确认后 `--强制` |
| 切换脚本「醒来后重复执行」→ 双驱动 | 原地改写了运行中的 bash 脚本（10:29 事故） | 铁律 2：`切换.sh` 已自复制；任何长跑脚本先复制再跑。已发生：杀第二驱动（pgrep 找最新的），`停跑.sh` 回收孤儿腿，`--resume` |
| `!! 已有切换在等（pid …）` | `<父目录>/.切换.lock` 残留或真有一个在等 | `kill -0 <pid>` 不活就 `rm` 锁；活着就别重复挂 |
| 切换等标记超时（默认 6 h） | 标记正则写错（转义 `\[`）或该事件不会再出现 | 先 `grep -E '正则' 驾驶_*.out` 验正则；用 `--最长` 缩短 |
| 钩子失败 `!! 钩子失败，不续跑` | 钩子异常（路径、台账 API） | 驱动已停净，可手工修再 `启动.sh --resume`；钩子先用 `--演练` 跑（`scripts/钩子样板.py`） |

## G 工具 / 环境类
| 症状 | 根因 | 修法 |
|---|---|---|
| bash 报 `未绑定的变量` / 变量名含中文 | macOS bash 3.2：变量名只能 ASCII；`$var` 后紧跟中文会把中文字节并进变量名 | 写 `${var}`；函数名可以中文 |
| `ps \| grep 中文` 永远不中 | macOS `ps` 把非 ASCII 命令行转义成 `M-x` | 进程判定一律 `pgrep -f`（`公共.sh` 已如此） |
| Claude Code 的 Bash 工具里 `sleep 45` 被拦 | 前台 sleep 被工具策略禁止 | 用 Monitor 盯日志，或 `看守.sh` 放后台任务；不要写轮询 |
| 相对路径突然失败 | 会话 cwd 漂进了镜像/skill 目录（工具会切目录） | 每条命令以 `cd /绝对/项目根 &&` 开头（铁律 13） |
| Codex 端起驱动失败/腿连不上端点 | 命令在沙箱内跑（无网、不能 kill 进程组） | 审批时选「在沙箱外运行」，或为工作区开 `network_access` |
| `setsid`/`timeout` 命令不存在 | macOS 没有 GNU 这两个 | 脚本已用 `start_new_session=True` / perl alarm 替代；别在新脚本里用 |
| `nohup … &` 起的驱动几十秒后消失 | 工具 shell 退出回收进程组 | 走 `后台启动.py`（`start_new_session`），`启动.sh` 已封装 |

## H 数据 / 镜像 / 角色同步类
| 症状 | 根因 | 修法 |
|---|---|---|
| 改了 `流水线/角色/*.md` 但腿行为没变 | 角色只在启动/续跑时同步进 `蜂巢镜像/角色/`（铁律 5/15） | 等下次续跑，或 `切换.sh` 在边界停/续 |
| 跑 `角色冒烟.py` 后活炉出问题 | 冒烟默认工作根就是 `真题测试/蜂巢镜像`，会同步资产并起真腿 | 用 `--根=<副本根>`；活炉期间绝不对着活镜像冒烟 |
| `--全新` 后旧成品没了 | S0 清空工作根重建 | 先归档：`cp -R 成品_xxx 归档_xxx`（成品目录在父目录下，不在镜像里，通常安全；镜像里的中间产物会没） |
| 续跑后 `论文/` 被旧版覆盖 | 旧版基座同步会覆盖 论文/（R39 已改为只播种不覆盖） | 看日志 `本地基座同步` 行；异常时从 `审稿/回退稿/`、`日志/*_修订前/` 找留底 |
| 契约核对报「未背书字段」 | 驱动/门检新读了一个角色没声明的字段（R13） | 在生产方角色 ```json 围栏里声明，或改消费方；这是硬门，不许绕 |

## I 腿引擎 claude（`--引擎=claude`）
| 症状 | 根因 | 修法 |
|---|---|---|
| 腿的 `.log` 空、进程一直活着、到 LEG_TIMEOUT 才 rc=142 | `claude -p` 在等 stdin EOF（从驱动/工具拉起时 stdin 是没关的管道） | 已在 `claude公共.sh` 里 `</dev/null`；自己手跑腿也要加 |
| 腿约 3 分钟后 `AUTO(rc=1)`，日志尾 `401 API key is invalid`，还带 `unrecognized_model` | 用户 `~/.claude/settings.json` env 块指向已退役的自定义端点；`--model` 被 env 的模型名覆盖 | **用户侧**修 settings.json 或 `claude /login`；本 skill 不动它。开炉前 `体检.sh --引擎=claude --探针` |
| 立刻 `Not logged in · Please run /login` | 没有登录态（或用 `--setting-sources project` 跳过了用户 settings） | 用户 `claude /login` |
| 第一波腿全部 rc=1 被当「腿死亡」重派 | 没做探针就开炉 | 停跑，`--探针` 通了再 `--resume`（引擎不变） |
| 腿把文件写到了工作根外 | claude 引擎没有 seatbelt | 换 `--引擎=codex`；或在 AGENTS.md 加硬约束并复盘 |
| 看图腿说「没看到图」 | 图路径不在工作根内，Read 被 acceptEdits 拒（读工作根外要审批） | 驱动传的是相对路径，正常在工作根内；手动冒烟时用相对路径 |
